# FE/BE 담당자에게 전달할 음성 대화 연결 규격

AI 코드를 FE나 BE 레포지토리에 복사하지 않습니다. BE가 AI의 HTTP API를 호출합니다. 아래는 구현해야 할 연결 계약이며 FE/BE 완성 코드가 포함된 것은 아닙니다.

## FE 담당 범위

- 사용자가 녹음 버튼을 눌렀을 때 `navigator.mediaDevices.getUserMedia({audio: true})`로 마이크 권한을 요청합니다. 권한 거절·장치 없음·장치 사용 중 상황에서는 텍스트 입력으로 전환할 수 있게 합니다.
- HTTPS 또는 localhost 환경에서 사용합니다. 원격 PC의 단순 HTTP IP 주소에서는 마이크 권한이 동작하지 않을 수 있습니다. 선택한 입력 장치가 내장 마이크인지 OS/브라우저 설정에서 확인할 수 있게 합니다.
- MediaRecorder로 녹음하며 `MediaRecorder.isTypeSupported()`로 `audio/webm;codecs=opus`, `audio/mp4` 등의 지원 형식을 확인합니다. 지원하지 않으면 무리하게 확장자만 바꾸지 말고 오류를 안내합니다.
- 녹음 종료 시 최종 dataavailable과 stop 이벤트 후 완성된 Blob을 보냅니다. webm이면 recording.webm, mp4이면 recording.mp4로 이름과 MIME을 맞춥니다. 파일을 단순히 이름만 wav로 바꿔도 WAV가 되지는 않습니다.
- Blob을 multipart/form-data의 `file`로 BE에 업로드합니다. FormData 전송 시 Content-Type 헤더를 직접 고정하지 않습니다. 브라우저가 boundary를 붙이도록 합니다.
- 인식된 글은 수정 가능한 초안으로 보여줍니다. 확인 후에만 BE에 대화 발언으로 제출합니다. 이것은 AI가 작성한 일기와 별개인 원문 확인 단계입니다.
- AI 질문 글과 재생/다시 듣기 버튼을 보여줍니다. 자동 재생이 차단되면 사용자가 누르는 재생 버튼으로 전환합니다.
- 'AI가 만든 음성입니다'라고 안내합니다. 실제 부모가 말하는 것으로 표현하지 않습니다.
- 음성이 재생 중이면 녹음 버튼을 비활성화하여 AI 음성이 아이의 발언으로 다시 녹음되지 않게 합니다. 필요하면 echoCancellation을 켜되 이것만으로 방지된다고 가정하지 않습니다.
- 녹음 종료/취소/페이지 이탈 시 스트림의 모든 트랙에 stop()을 호출해 마이크를 끕니다. 취소한 녹음은 업로드하지 않습니다. 오디오 URL은 재생이 끝나고 더 이상 쓰지 않을 때 revokeObjectURL로 정리합니다.
- 한 요청 처리 중 중복 전송을 막고, 초과 길이·통신 실패 때 입력을 보존합니다. 발화 단위 60초 등 FE의 녹음 제한을 별도로 두세요.

권장 화면 상태:

```text
대화 시작 → 질문 재생 → 녹음 준비 → 녹음 중 → 전사 대기
 → 전사 확인/수정 → 질문 생성 대기 → 질문 재생 → 반복
```

계속 듣기와 자동 침묵 감지는 이번 AI 패키지에서 구현하지 않았습니다.

## BE 담당 범위

- 인증한 사용자/대화 세션에 업로드를 연결합니다. 녹음 파일의 크기와 개수를 요청 파싱 전부터 제한하고 시간 초과를 설정합니다. AI 쪽의 최대 파일 크기는 8 MiB입니다.
- `/api/transcribe`에는 multipart file만 전달합니다. 원본 파일명에 개인정보가 있으면 BE에서도 중립적인 이름으로 바꿉니다.
- 전사 초안을 바로 확정된 child 발언으로 저장하지 않습니다. 사용자가 확인·수정한 텍스트를 받아 반영합니다.
- 순서가 유지된 전체 messages로 `/api/voice-chat`을 호출합니다. 첫 질문에는 빈 배열을 사용합니다.
- 성공한 question을 assistant 메시지로 한 번만 저장합니다. 음성 합성만 실패했을 때는 질문을 재생성하지 않습니다.
- audio_base64를 MP3 바이트로 변환해 FE에 전달하거나, 기존 팀의 파일 저장소에 저장하고 접근 가능한 URL을 반환합니다. 오디오/대화를 서버 로그에 출력하지 않습니다.
- 원음 보관은 별도의 동의·정책과 함께 결정합니다. AI 서비스는 원음을 영구 저장하지 않습니다. 업로드 프레임워크가 처리 중 임시 파일로 스풀할 수 있으며 AI 핸들러가 처리가 끝나면 닫습니다.
- 요청 파싱 이후 검사만으로 대용량 업로드 공격이 차단되는 것은 아닙니다. BE/리버스 프록시에서 multipart 전체 크기(메타데이터 포함), 호출 횟수, 동시 요청을 제한하세요.
- AI 서비스는 사용자 인증 API가 없으므로 공개 노출하지 않고 내부 접근 및 서비스 인증을 구성합니다.
- 일기/그림책 생성과 날짜별 저장은 기존 흐름을 유지합니다. 일기에는 확인한 텍스트 발언만 사용합니다.

## 시간 초과와 재시도

음성 인식과 음성 합성 모델 호출은 각각 60초로 설정되어 있습니다. voice-chat은 질문 생성·검토·음성 합성을 순차 수행하므로 BE 대기 시간을 이에 맞춰 설정합니다(개발 예: 180초). 전체 장치 녹음 시간이 이 서버 타임아웃에 포함되는 것은 아닙니다.

음성 인식·질문·음성 합성은 각각 유료 호출입니다. 실패했다고 전체 대화 요청을 자동 반복하지 않습니다. 현재 중복 요청 제거 저장소는 없으므로 BE에서 요청 ID/중복 방지 처리를 구현해야 합니다.
