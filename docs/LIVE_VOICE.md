# 마이크 대화 개발 테스트

## 실행

1. .env에 `ENABLE_VOICE_DEMO=1`을 추가합니다. Groq 키와 `AI_MODE=openai`, `TEXT_PROVIDER=groq`, `STT_PROVIDER=groq`가 필요합니다.
2. 기존 서버를 중지한 후 다시 실행합니다. `python server.py` 또는 VS Code의 실제 AI 실행 설정 중 하나만 사용합니다.
3. 같은 Mac의 브라우저에서 <http://127.0.0.1:8002/dev/voice>를 엽니다.
4. 마이크로 대화 시작을 누르고, 본인이 브라우저 마이크 권한을 허용합니다.
5. 첫 질문을 듣고 답합니다. 말을 마친 뒤 기본 3초 동안 조용하면 자동으로 음성을 인식합니다. 말 끝났어 버튼으로 직접 끝낼 수도 있습니다.
6. 인식한 글을 확인·수정하고 이 내용으로 보내기를 누릅니다. 다음 질문을 읽은 뒤 자동으로 다시 듣습니다.
7. 성인 시연에서 자동으로 이어가려면 인식한 글을 확인한 뒤 보내기 체크를 해제합니다. 오인식도 바로 전달되므로 최종 일기를 반드시 확인합니다.
8. 일시정지 · 마이크 끄기로 녹음을 종료합니다. 대화 마치고 일기 쓰기로 확인한 발언을 정리합니다.

이 화면은 성인 개발자의 시연용입니다. 실제 아동 대상 운영의 연령·데이터 처리 조건은 별도 확인이 필요합니다.

## 처리 방식과 한계

수동으로 녹음 파일을 저장하거나 선택할 필요가 없습니다. 브라우저는 MediaRecorder로 발화 하나를 메모리에 녹음하고, 말이 끝나면 기존 /api/transcribe에 자동으로 전송합니다. 즉 단어가 나오는 순간마다 서버가 인식하는 스트리밍 STT나 동시 양방향 통화가 아니라 발화 단위로 번갈아 대화하는 방식입니다. Groq 인식과 질문 생성에 시간이 걸리므로 답변 사이에 기다림이 있습니다.

흐름은 `마이크 → 말 끝 감지 → /api/transcribe → 원문 확인 → /api/chat → 브라우저 한국어 음성 → 마이크`입니다. 그림 생성이나 OpenAI TTS 호출은 이 화면에서 자동으로 실행하지 않습니다.

기기 음성 출력은 브라우저 SpeechSynthesis를 사용합니다. 설치된 한국어 음성 중 로컬 음성을 우선 선택하며 없으면 기본 ko-KR 음성을 요청합니다. 실제 목소리·지원·처리 위치는 브라우저/OS에 따라 다릅니다. 한국어 음성이 재생되지 않으면 마지막 질문 다시 듣기 또는 읽기 체크 해제 후 텍스트로 시험하세요. Chrome에서 먼저 시험하는 것을 권장합니다. 마이크 사용은 localhost 또는 HTTPS 환경이 필요합니다. 다른 컴퓨터에서 HTTP IP 주소로 열면 마이크를 사용할 수 없을 수 있습니다.

말 끝 대기 시간은 1.8/3/5초로 선택합니다. 배경 소음이 크면 자동 종료가 지연될 수 있으므로 말 끝났어를 누릅니다. 한 번의 발화는 최대 30초, 전송 파일은 기존 서버 제한과 같은 8 MiB입니다. 조용한 상태가 30초 지속되면 API 호출 없이 대기합니다. 소음 감지는 단순 음량 기반이므로 사람의 말인지 완벽히 판단하지 못합니다. 인식 결과 확인이 기본으로 켜져 있습니다.

AI 질문 재생·전사·생성 중에는 녹음을 하지 않습니다. 일시정지, 다른 탭으로 이동, 페이지 종료 시 마이크 트랙을 종료하고 요청을 취소합니다. 이미 제공업체로 전송된 요청은 브라우저 취소만으로 공급자 처리나 과금까지 취소되는 것은 아닙니다. 늦게 도착한 응답은 대화에 추가하지 않습니다.

대화는 화면 메모리에만 보관합니다. 새로고침 전에 대화 내려받기로 JSON 파일을 저장할 수 있습니다. AI 서버는 기존과 같이 녹음이나 대화를 DB에 영구 저장하지 않습니다.

## FE·BE 개발자에게

- devtools/voice는 AI 담당자가 기능 연결을 검사하는 별도 개발 도구입니다. 제품 FE나 날짜별 저장 기능은 포함하지 않습니다.
- 기존 9개 API와 JSON 계약은 유지합니다. 추가 /dev/voice 경로는 ENABLE_VOICE_DEMO=1일 때만 로컬 요청에 제공하며 OpenAPI 문서에는 나타나지 않습니다. 배포 시 이 설정을 0으로 바꿉니다.
- 마이크·음량 감지·재생·전사 수정은 FE 담당입니다. BE는 인증, 대화 보존, 날짜별 일기 저장을 담당합니다.
- 전사는 자동으로 대화에 넣지 말고 확인된 text를 child 메시지로 전달합니다. /api/chat에는 이전 대화를 포함한 전체 messages 배열을 보냅니다.
- 질문 API가 실패하면 대화 이력에 같은 발언을 중복 추가하지 않고 초안을 유지해 재시도합니다.

## 파일과 주요 변수

| 파일/변수 | 역할 |
| --- | --- |
| dev_voice.py | 활성화 설정과 로컬 접근 검사, 개발 화면 제공 |
| devtools/voice/app.js | 마이크·음성·API 연결, UI 상태 제어 |
| devtools/voice/core.mjs | 발화 종료 감지와 대화 이력 처리 |
| ENABLE_VOICE_DEMO | 1이면 로컬 개발 화면 활성화, 기본은 0 |
| active / phase | 대화 실행 여부와 현재 듣기·확인·생성·재생 상태 |
| revision / Conversation.version | 중지 전 시작한 비동기 결과를 무시하는 번호 |
| stream / recorder | 마이크 스트림과 발화별 녹음기 |
| monitor / analyser | 음량 측정 타이머와 Web Audio 분석기 |
| pending | 중지할 수 있는 HTTP 요청의 AbortController 집합 |
| TurnDetector.silenceMs | 말 끝으로 판단하는 무음 시간 |
| TurnDetector.voiceMs | 짧은 잡음을 제외하기 위한 음량 감지 누적 시간 |
| MAX_BYTES | 한 발화당 최대 8 MiB |
| conversation.messages | 확인한 발언과 완료된 질문의 전체 이력 |

## 검증

Python API 테스트와 Node의 상태 처리 테스트는 실제 마이크·외부 API 없이 실행합니다. 실제 한국어 발화 인식률, 기기 음성 재생, 소음 환경, 브라우저 권한은 사용자가 장치에서 직접 확인해야 합니다.

```bash
python -m pytest -q
node --test tests/test_voice_browser.mjs tests/test_voice_ui.mjs
```

참고: [Groq STT](https://console.groq.com/docs/speech-to-text), [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder), [기기 음성](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis).

그림 생성·저장 단계는 [그림일기 안내](ILLUSTRATED_DIARY.md)를 참고하세요.

일기를 확인한 뒤 직접 그림을 그리고, 왼쪽 그림일기와 오른쪽 AI 4컷 만화를 만들 수 있습니다. [현재 그림일기 안내](CHILD_DRAWING_DIARY.md)를 참고하세요.

### 음성 말투

대화는 짧고 다정한 구어체를 사용합니다. 서버 TTS(`/api/speech`, `/api/voice-chat`)의 말하기 지침은 `prompts.py`의 `TTS_INSTRUCTIONS`에서 관리하며, 따뜻한 어조·자연스러운 문장 연결·짧은 쉼을 요청합니다. 입력 문장은 그대로 읽습니다. 데모의 기기 음성에는 서버 TTS의 억양 지침이 적용되지 않습니다. 실제 자연스러움은 사용하는 음성으로 들어 보며 확인해야 합니다.
